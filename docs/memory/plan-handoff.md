用户常把设计和实现分开：在一个会话里讨论并定稿方案，再交给新会话实现。这时：

- 方案写在 `docs/<主题>-plan.md`，例如 `docs/admin-page-plan.md`；不要写代码。
- 方案要自包含：开头写明先读哪些文档，再写目标、范围外、架构、分步改动、测试、验收、留给实现者的判断。
- 讨论中每定一个点，就更新到同一份方案里，不另开文件。
- 和已有做法的对比、做出某个决定的原因，也写进方案，方便接手的会话理解。

**原因：** 用户要把方案直接交给别的会话，那个会话看不到这里的讨论。
**怎么用：** 听到"拟一份方案""我交给别的会话"时照此执行；实现完成后，方案文档的"状态"改为已实现，或者删掉并把结论并入 `AGENT_WORKFLOW.md`。
