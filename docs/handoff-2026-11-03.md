## 三、已确认的问题

### P0 停止运行中的值守会失败（disarm / resume --kill-stale）

- 现象：值守运行时执行 `disarm`，报 `进程身份无法确认，拒绝终止；请人工检查。`
- 复现（不布防也能验证）：

  ```sh
  python3 -B - <<'PY'
  import os, subprocess, sys, time
  sys.path.insert(0,'src')
  import manage, night_watch as nw
  p = subprocess.Popen(["/usr/bin/caffeinate","-dimsu",sys.executable,"-B","-c","import time;time.sleep(20)"],
                       start_new_session=True)
  time.sleep(1)
  print(manage.command(p.pid))          # 实际是 python 的命令行，不含 caffeinate
  try: nw.stop_watch({"pid": p.pid})
  except Exception as e: print(type(e).__name__, e)
  os.killpg(p.pid, 15)
  PY
  ```

- 原因：`night_watch.spawn_watch()` 记录的是 `caffeinate` 的 Popen pid；在这台 macOS 上 caffeinate 会 fork 一个断言子进程并让**父进程 exec 成实际命令**（python），所以该 pid 的命令行是 `python3 … night_watch.py run --generation …`，不含 `caffeinate`。`stop_watch()` 却要求命令行包含 `caffeinate`。
- 影响：`disarm`、`resume --kill-stale` 都无法停止值守；用户只能手动 `kill`。目前没有别的路径。
- 建议修法：`stop_watch()` 的身份校验改为「命令行包含本文件绝对路径 + `run` + generation」且 `os.getpgid(pid) == pid`，去掉 `caffeinate` 要求；必要时再用 `ps -o ppid=` 或 pmset 断言确认 caffeinate 子进程。改完补一条单测。
